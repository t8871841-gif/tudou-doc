## 第 1 批：第 12、13 条

### 12 悬浮球短按修复
根因（已定位）：`OrbController.tap()` 在 `dartAlive` 且前台服务在跑时只投递事件、没有回执也没有兜底，事件被吞就零反馈；`OrbView` 用原始 touch slop 判拖动，点按的轻微位移被当成拖动吃掉。

改法：
- 短按优先通知 Dart 开始聆听，**要求 Dart 回执**（MethodChannel 回调结果）。
- 兜底：投递条件不满足、Dart 回 false / 报错 / 没实现、或 1.5 秒无回执，一律 `launchApp("assist")` 拉起 Jarvis 并聆听，同时弹“正在唤起 Jarvis…”气泡。
- 点中立即触觉反馈（`performHapticFeedback`，不需要 VIBRATE 权限；忽略系统“触感反馈”总开关）。
- 拖动阈值 = 系统 touch slop × 2.5。
- Dart 侧 `_onOrbTap` 每个状态都有可见反馈（球变色 / 气泡），不静默：待命 → “我在听…”并开始聆听；聆听中 → 结束本轮；播报中 → 打断；思考中 → “正在处理，请稍等…”；启动页 → 静默进入后聆听；无法处理 → 返回 false 交给原生兜底。

### 13 悬浮球外观重做
- 去掉深色圆饼与麦克风图标，改为同心三层、全部渐变色：外层环绕渐变环（SweepGradient，非待命时缓慢旋转，约 36°/秒）、中层径向渐变圆盘、核心高光渐变 + 光晕。
- 颜色随状态：待命蓝 / 聆听青 / 思考橙 / 播报绿。

## 第 3 批：第 4 条 视觉看屏

### 做了什么
- **截图通道（原生）**：无障碍服务 `takeScreenshot`（Android 11+）→ 缩到最长边 1280、JPEG 70% → base64；同时算 16×16 灰度签名，**本地**判断“屏幕变没变”，不上云。
- **坐标动作（原生）**：`dispatchGesture` 实现按坐标点击和竖向滑动。
- **视觉服务 `vision_service.dart`**：`ask`（看一眼屏幕回答问题）、`locate`（找目标元素坐标）、`decideNext`（纯视觉模式下决定下一步）、`verify`（视觉核验）。走用户自己配置的 OpenAI 兼容多模态接口，默认复用主模型的接口 / Key，可单独配置；坐标格式可选像素或 0~1000 归一化。
- **与节点树融合（`agent_loop.dart`）**：节点树优先。
  1. 树读不到（无可读内容）或读不全（有意义的文字 / 描述节点少于 2 个）→ 进入纯视觉循环：看图 → 决定 → 坐标动手 → 本地签名判断屏幕是否变化 → 视觉核验“完成”，最多 6 轮、连续 2 轮无进展即停；
  2. 树里点不到目标 → 截图 → 视觉模型定位 → 坐标点击；
  3. 铁律沿用：“做完了”必须核验到才算数，失败如实说卡在哪；每一步都进审计日志，急停同样生效。
- **看一眼屏幕回答问题**：对 Jarvis 说“这上面写了什么 / 看一下屏幕 / 这个按钮在哪”，截图后由视觉模型回答。
- **设置**：设置 > 视觉看屏（开关、模型、接口、Key、坐标格式）；功能自检页新增“视觉看屏”一行，显示最近一次截图失败原因。

### 隐私与安全
- 截图只发往用户在设置里配置的接口；每次上传都会在操作日志里记一条（应用包名 + 用途）。
- **黑名单**（包名含 bank / wallet / pay / finance / security / alipay / unionpay / 常见银行缩写 / settings / packageinstaller / permissioncontroller）直接拒绝截图，并明确提示“当前界面属于银行 / 支付 / 钱包 / 系统设置类，不会截图也不会上传”。
- 另外拒绝：Jarvis 自己在前台（会截到自己）、无法确认前台是哪个 App、系统防截屏窗口（FLAG_SECURE）。
- **坐标点击 / 滑动**只在“不在黑名单 且 在看屏白名单内”的 App 里允许；短视频 / 游戏类 App 需先把包名加到看屏白名单，否则明确提示。
- 视觉未启用、没配 Key、或 Android 低于 11 时，全部降级为 v2 行为（读不到就如实失败），不影响现有功能。

### 局限（如实）
- “读不全”的判定是启发式（文字 / 描述节点少于 2 个），可能误判或漏判；误判的代价是多一次云端截图。
- 点击精度取决于所配模型的定位能力；不支持图片输入的模型会报错，并提示确认模型。
- 截图是整屏，黑名单只按前台包名判断，屏幕上其他可见内容会一并上传。
- 回答“看一眼屏幕”需要 Jarvis 不在前台：用悬浮球（建议开启后台常驻）或电源键唤起；Jarvis 在前台时会提示先切到目标界面。

## 第 4 批：第 5 条 唤醒词（降级方案）

### 结论先说
**没有接入专用 KWS 模型，仍是“离线语音识别持续解码 + 匹配‘贾维斯’文本”**（v2 就是这么做的）。原因：沙箱无网络，拿不到 sherpa-onnx 的 KWS 模型文件；且 KWS 的 Dart 接口在没有编译环境的情况下无法验证，写错会让整个构建失败。这一条因此按“降级方案”交付，并且**没有给出耗电数字**——没有实测也没有可信的估算依据，不编；改为把实测做进了 App（见下）。

### 做了什么
- **设置里可开关**：设置 > 语音唤醒 > 语音唤醒待命。持久化，并与主界面唤醒词胶囊双向同步（启动时按设置恢复）。
- **可调灵敏度**：严格 / 标准 / 宽松。严格 = “贾维斯”须在句首 3 字内且整句不超过 30 字；标准 = 句首 6 字内（v2 原有匹配）；宽松 = 句中任意位置，并容忍更多误听写法（假维斯、嘉韦思等）。
- **误唤醒控制**：
  1. 冷却：刚唤醒 3 秒、刚误唤醒 8 秒内忽略唤醒词；
  2. 唤醒后约 5 秒（两次空白断句）或 10 秒总时限内没有有效指令（空白 / 只有“嗯、啊、呃”这类语气词）→ 自动回待命，并记一次误唤醒；中途一旦识别到真实内容，就恢复正常 60 秒聆听；
  3. 10 分钟内误唤醒 ≥3 次 → 自动临时调到“严格”10 分钟并提示；
  4. 唤醒与误唤醒都写入操作日志。
- **唤醒后直接聆听**：沿用 v2 流程；后台唤醒时给悬浮球弹“我在听…”作为可见反馈。
- **与现有入口并存**：悬浮球点击、电源键默认助手、唤醒词都经 `_state` 门禁进入同一个聆听流程，互斥不重入；唤醒识别只在待命态运行。
- **待命耗电实测工具**：唤醒词待命开始时记下电量与时间（`StandbyMeter`），在 功能自检 > 唤醒监听 里用真实电量变化折算 %/小时；样本不足 20 分钟、期间充过电、关闭 / 静音唤醒或进程被杀都会明确说“无效 / 样本不足”。电量只有整数百分比，样本越长越准。
- **功能自检**：唤醒监听一行现在显示灵敏度、是否被临时调严、本次运行唤醒 / 误唤醒次数、待命耗电实测。

### 验收对应与边界
- “息屏 / 其他 App 前台时喊‘贾维斯’能唤醒并听指令”：依赖 v2 的**后台常驻（前台服务）**在运行且有录音权限；没开常驻时，应用退到后台后系统可能停掉麦克风。**未在真机验证。**
- 熄屏下识别器持续解码，耗电高于专用 KWS 方案，这是降级的主要代价。要换成 KWS，替换点在主界面 `_startWakeListening`：把待命态的 `_asr.start(onEndpoint: _onWakeUtterance)` 换成 KeywordSpotter，其余灵敏度、冷却、误唤醒逻辑可以原样复用；需要自备 KWS 模型（如 sherpa-onnx 的 zipformer wenetspeech 3.3M KWS，约十几 MB，放 assets），包体增量以所选模型为准。
- 灵敏度是文本匹配层面的调节，不改变声学模型的检出率。

## 第 5 批：第 6 条 打断说话（降级版）

### 实现等级：B（降级版，不是完整 AEC）
完整的回声消除（把自己喇叭里的声音从麦克风信号里减掉）在这套架构里做不到，所以按需求文档的降级口径交付：**播报时检测到用户持续说话 → 停播并聆听**。

### 做了什么
- 播报开始时（设置里开了“打断说话”），打开识别器监听麦克风；识别器本身沿用 v2 的录音配置（`echoCancel`、`noiseSuppress`、`autoGain` 都已开启，走平台回声消除）。
- **回声过滤（文本层）**：识别结果如果是“自己正在播的内容”（已播文本的子串，或双字片段 ≥75% 出现在已播文本里）就忽略，并重新计时。
- **触发规则**：
  - 说“停 / 停下 / 别说了 / 够了 / 等一下 / 暂停 / 闭嘴”：识别到就立刻停播；
  - 说别的：要连续识别到“非回声”内容约 0.35 秒以上才算持续说话，避免咳嗽、杂音误触发。
- **触发后**：作废还在生成的回答、停播报、停流式输出，把用户说的这句话接着听完——停止词则直接回待命，其他内容当作新问题发出去（去掉开头的“贾维斯”）。写入操作日志。
- 播报结束或被其他入口打断时，会关掉监听用的识别器，不留着麦克风。
- 设置：设置 > 语音：唤醒与打断 > 打断说话（默认开，可关）。功能自检新增“打断说话（降级版）”一行，显示是否启用、录音权限、本次运行打断次数。

### 验收对应与边界
- “长播报中途说‘停’或直接提新问题，播报在约 1 秒内停下”：停播动作本身是立即的，耗时主要取决于识别器出第一个结果的延迟；**没有实测，不给延迟数字**，请真机用长回复测一次。
- 平台回声消除是否真的生效取决于机型 / ROM（未实测，Flyme 不确定）；喇叭音量很大或回声被识别成与播报不相似的文字时，可能误触发（把回声当人声）或漏触发。遇到误触发就在设置里关掉。
- 打断只在 Jarvis 自己播报时监听；唤醒词待命态已有识别器在跑时，不重复开监听。

- 原生：无改动。通道仍为 35 个方法，无变化。

- 新增权限：**无**；新增依赖：**无**；无需重新开关无障碍服务。

## 第 6 批：第 7 条 主动性

### 来电 / 短信 / 通知播报
- 原生通知监听把新通知实时推给 Dart（只在设置里开了播报时才推，不落盘），由 `announce_service.dart` 决定播不播、播什么。
- 规则链：总开关 → 来源开关（短信 / 来电 / 微信，另可补自定义包名）→ **勿扰时段不播**（默认 22:00–07:00，支持跨午夜）→ 联系人 / 发件人白名单（留空 = 全部）→ **验证码类只提示“收到一条验证码类通知，内容已隐藏”，不读内容**（沿用 v2）→ 超过 50 字的消息用大模型压成一句（优先本地模型，6 秒超时则截断）→ 8 秒内重复通知去重。
- 来电：靠拨号器的来电通知识别（按 `CATEGORY_CALL` 放行带“常驻”标志的来电通知），播“来电：某某”。
- 只在 Jarvis 空闲时播（不打断正在进行的对话 / 聆听 / 播报）；每条播报写入操作日志；急停与静音照常生效。
- 设置：设置 > 主动播报与出发提醒。功能自检新增“来电 / 短信 / 通知播报”一行（是否授权通知读取、后台常驻是否在运行）。

### 出发提醒（简化 / 降级）
- 读未来 24 小时内**有地点**的日程（非全天），在开始前提醒“该出发了”，文字里写明依据：
  - 有定位权限且地点能被地理编码 → 直线距离 × 1.3 绕行系数 ÷ 30 km/h 粗估路程，再加 10 分钟缓冲，标注“按直线距离粗估路程”；
  - 否则 → 按设置里的固定提前量（默认 30 分钟），标注“按固定提前量”（**降级**）。
- 没有路径规划接口，估算只是粗估，不是导航级 ETA；地点是地址而不是地名时，地理编码常常查不到，会落到固定提前量。
- 排程发生在 Jarvis 运行时（启动、改设置、晨报播报后）：**当天一次都没打开过 Jarvis 就不会排程**。提醒走 v2 的系统闹钟式提醒，排上后熄屏也准点。
- 功能自检新增“日程出发提醒”一行（日历权限、通知权限）。

### 验收对应与边界
- 通知播报要在后台生效，需要：通知读取授权 + 后台常驻在运行（否则 Jarvis 进程可能不在，收不到）。
- 不同 ROM 的拨号器 / 短信应用包名不同，内置了常见包名；没播的请在“额外包名”里补。**Flyme 的包名我没有实测。**
- 摘要质量取决于所用模型；播报文案不含验证码内容。

## 第 7 批：第 8 条 技能固化（在现有 SkillStore 上扩展）

### 做了什么
- **扩展而不是推翻**：`Skill` 新增两个可选字段——`uiSteps`（看屏流程的界面步骤，每步含动作、目标、输入、**核验点**）和 `goalPattern`（带变量的目标模板）。旧数据没有这两个字段时按空处理，v2 的 skill 行为完全不变；`matchSkill` / `recordSuccess` / `recordFailure` 只增加了“模板感知”。`UiStep`、`UiTrace`（一次任务的内存轨迹）放在 `skill_store.dart` 里，没有另起存储。
- **记录**：看屏执行成功的每一步（节点树路径和视觉路径都记）进入本次任务的轨迹。
- **触发保存**：任务成功后，若轨迹满足“≥2 步、整个任务只有 1 个看屏步骤、不是回放出来的、不含密码 / 验证码 / 6 位以上数字”，Jarvis 在回复末尾询问；用户说“记住这个流程”或“以后都这样做”才保存（新任务开始时旧询问作废）。保存后回复会说明变量。
- **参数化**：call / message / navigate 沿用既有变量名 `{contact}{body}{destination}`；generic 意图把“打进去的文字”（input）且原话里也有的词变成 `{p1}{p2}…`，目标句式与规划步骤里的同一批词同步模板化。**点击的目标（按钮 / 列表项名）保持字面量**，所以换成别的值就匹配不上、不会复用，而不是拿旧目标去乱点。
- **复用**：命中带界面步骤的 skill 时，先把变量替换好并在状态栏和操作日志里**明示变量值**，再在第一个看屏步骤上**逐步回放**：每步动作必须成功；有核验点就必须在新屏幕上看到，没有核验点就必须看到屏幕变化；节点树点不到时可走视觉定位（若已启用）。
- **失败不静默**：任何一步对不上就立即停下，提示“已学会的流程回放没对上（原因），改用看屏代理重新做这一步”，作废过期的界面步骤（规划步骤保留），写操作日志，然后回退到原来的看屏代理（它自带逐步核验）；回退做成功后会重新询问是否保存新流程。
- **管理**：设置 > 自检与记录 > 已学会的流程，可查看、删除（只删界面步骤，保留规划步骤）。模板复用成功时只复位失败计数，不会用这次的具体值覆盖模板；连续失败 2 次沿用原有规则自动停用。

### 局限（如实）
- 参数识别是启发式：只有“打进去的文字”会成为变量。选联系人这类“点击选择”的值是字面量，因此那类流程只在同一目标下复用。
- 规划步骤里没出现在界面步骤中的个性化文字不会被模板化；复用前会把变量值展示出来，但**不会再让你确认一遍**。
- 回放只在整个任务的第一个看屏步骤上做；有多个看屏步骤的任务不会被询问保存。
- 回放依赖界面文字与保存时一致；App 改版后会在某一步对不上并回退，这是预期行为。
